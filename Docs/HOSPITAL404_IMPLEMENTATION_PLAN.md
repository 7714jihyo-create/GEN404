# 종합병원 404 구현 설계

## 구현 목표

기존 `StartScene → GameScene → WaitingScene → ResultScene` 흐름은 유지하되, 각 진료 라운드에서 플레이어가 환자 차트를 확인하고 진단서와 처방을 제출하면 치료 후일담과 점수를 받도록 확장한다. 기본 플레이는 네트워크 연결 없이도 동작해야 하므로, 게임 내의 이야기 생성기는 환자별 키워드와 결과 템플릿을 조합하는 로컬 규칙 엔진으로 구현한다. 실제 생성형 AI 연결은 별도의 보안 서버가 준비됐을 때 선택적으로 추가한다.

## 게임 상태

| 항목 | 내용 |
| --- | --- |
| 라운드 수 | 총 3라운드 |
| 라운드 시작 | `GameScene` 진입 또는 결과 확인 후 다음 환자 호출 |
| 플레이어 입력 | 진단명과 처방을 각각 입력 |
| 결과 산정 | 처방 키워드와 환자의 효과·금기 키워드를 비교하여 성공, 부분 성공, 실패, 방치 중 하나로 판정 |
| 점수 | 성공 100점, 부분 성공 60점, 실패 20점, 방치 0점이며 진단 작성 보너스 최대 10점 적용 |
| 종료 | 3라운드 후 `ResultScene`에 총점·등급·진료 요약 표시 |

## 환자 차트 모델

`PatientData`는 이름, 종족, 연령대, 병명, 주요 증상, 특약·알레르기·금기 중 하나, 효과 키워드, 위험 키워드, 서사 소재를 보유한다. 기본 환자 풀에는 냉장고, 강아지, 전자레인지, 와이파이 공유기, 청소 로봇, 외계인을 배치하며, 매 세션에서 중복 없이 세 명을 선택한다.

## 치료 판정 규칙

처방이 비어 있으면 방치 판정이다. 처방에 환자의 위험 키워드가 하나라도 포함되면 실패 판정이며, 효과 키워드를 두 개 이상 포함하면 성공, 한 개 포함하면 부분 성공이다. 키워드가 하나도 맞지 않아도 의학적으로 무해한 황당 처방은 실패에 가까운 부분 결과로 표현하여 플레이어의 입력이 언제나 후일담에 반영되도록 한다.

## 화면 구성

| 화면 | 구현 방식 |
| --- | --- |
| `GameScene` | 기존 진료실 배경 위에 런타임으로 차트, 진단·처방 입력, 제출 버튼, 결과 보고서 모달을 생성한다. 기존 차트 버튼은 차트 모달 열기로 연결한다. |
| `WaitingScene` | 새 라운드가 열릴 때 현재 라운드와 다음 환자를 알리는 간단한 전환 패널을 런타임으로 생성한다. |
| `ResultScene` | 총점, 평가 등급, 3개 환자의 요약 결과, 다시 진료하기 버튼을 런타임으로 생성한다. |
| `StartScene` | 기존 시작 버튼을 그대로 사용한다. 시작 이벤트에서 새 세션을 초기화한다. |

## AI 연동 원칙

게임 클라이언트에 API 키를 저장하지 않는다. 향후 AI 보고서를 추가하려면 `DiagnosisResultBuilder`의 결과 객체를 HTTPS 서버로 전송하고, 서버에서만 모델 API 키를 사용한다. 응답이 지연되거나 실패한 경우에는 즉시 로컬 템플릿 결과를 표시해 게임 진행을 보장한다.

## 수용 기준

1. 게임 시작 시 환자가 새로 배정되고, 차트에 실제 환자 정보가 표시된다.
2. 진단명과 처방을 제출하면 4~5문장에 가까운 치료 결과와 점수가 표시된다.
3. 결과 확인을 세 번 반복하면 최종 결과 화면으로 이동한다.
4. 재시작하면 점수와 라운드가 초기화된다.
5. 결과 씬이 빌드 설정에 포함되어 빌드에서도 정상 전환된다.
